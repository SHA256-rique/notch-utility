# 03 — macOS API field notes

Specifics that cost real time to work out. Mostly things that are true, matter,
and are not in the documentation in a form you would find by searching for them.

---

## Detecting the notch

`NSScreen.safeAreaInsets.top > 0`. That is the reliable signal.

Two alternatives that look right and are not:

- **Hardcoding model identifiers.** Breaks on every new Mac.
- **`auxiliaryTopLeftArea` / `auxiliaryTopRightArea` alone.** These *do*
  describe the menu-bar regions either side of the cutout, but they go `nil`
  when the menu bar is auto-hidden or a screen is in full-screen — precisely
  when you still need to position the panel. `safeAreaInsets` keeps reporting
  through both.

For the exact cutout **width** (which differs between the 14"/16" Pro at ~200pt
and the Air at ~170pt), the gap between the two auxiliary areas is exact when
they are available:

```swift
let width = right.minX - left.maxX
```

Use it when available, fall back to a sane constant otherwise.

## Non-activating panels

`.nonactivatingPanel` means clicking the panel does not steal focus from the
user's app. Essential — otherwise tapping a timer yanks focus out of their
editor.

The consequence people hit: **a borderless panel returns `false` from
`canBecomeKey`**, so every text field inside it is inert. You have to opt in:

```swift
override var canBecomeKey: Bool { wantsKeyboardFocus }
```

and flip that stored property when opening a tab that needs typing, after
`NSApp.activate(ignoringOtherApps:)`. Order matters — the app must be active
before the panel can meaningfully take key status.

Related trap: **`NSOpenPanel` from a non-activating accessory app opens behind
everything** unless you activate first. Every call site in this codebase does.

## Window resize vs SwiftUI animation

Do not animate both. Letting AppKit animate `setFrame` *and* SwiftUI animate the
content produces the rubber-banding this app category is known for.

What works: `animationBehavior = .none`, `setFrame(_:display:animate:false)` —
the window snaps — and all visible motion is a SwiftUI spring inside a window
that is already big enough.

## `sharingType = .none`

Makes a window invisible to screen recording, screen sharing and screenshots at
the window-server level. Same mechanism password managers use. One line:

```swift
window.sharingType = .none
```

It defeats *software* capture on the same machine. It is not a defence against a
camera pointed at the screen, and it does not survive some virtualisation setups.
Say so to users rather than implying more.

## IOKit power sources

```swift
IOPSNotificationCreateRunLoopSource({ ctx in ... }, context)?.takeRetainedValue()
```

`takeRetainedValue`, not `takeUnretainedValue` — the Create rule applies and you
own the returned source.

The callback is a bare C function pointer with a `void *` context and **cannot
capture**. Pass `Unmanaged.passUnretained(self).toOpaque()` and recover it with
`Unmanaged<T>.fromOpaque(ctx).takeUnretainedValue()`. Unretained is safe only
because the owner is a singleton that outlives the source.

`kIOPSTimeToEmptyKey` returns **-1** when macOS is still calculating. Showing
"-1 min" is worse than showing nothing.

Low Power Mode is a *separate* notification: `.NSProcessInfoPowerStateDidChange`.

## mach statistics

```swift
var size = mach_msg_type_number_t(MemoryLayout<host_cpu_load_info>.size
                                  / MemoryLayout<integer_t>.size)
```

The size is in **`integer_t` units, not bytes**. Getting this wrong gives
`KERN_INVALID_ARGUMENT` with no further hint.

`HOST_CPU_LOAD_INFO` returns monotonically increasing tick counters, so a
percentage needs **two samples**. Drop your baseline on teardown — otherwise
re-opening a tab computes an average across the whole idle gap and reports a
nonsense spike.

For memory, match Activity Monitor's "Memory Used":

```swift
active + wired + compressed        // NOT total - free
```

`total - free` reads as ~90% on every healthy Mac because macOS uses free RAM
for cache. Your widget will look broken and users will report it as a bug.

For disk, use `volumeAvailableCapacityForImportantUsageKey`, which accounts for
purgeable space the way Finder does, rather than raw statfs blocks.

## Pasteboard

There is no change notification. Everyone polls. Poll `changeCount` — one
integer, cheap — and only touch real data when it moves. Calling
`string(forType:)` every tick forces the *owning app* to re-render its data on
every poll.

Respect the community conventions, which are real pasteboard types:

```
org.nspasteboard.ConcealedType        password managers, secure fields
org.nspasteboard.TransientType        short-lived internal drags
org.nspasteboard.AutoGeneratedType    machine-generated
```

Honouring `ConcealedType` is the difference between a clipboard manager users
trust with a 1Password copy and one they uninstall.

When your own app writes to the pasteboard, suppress your next read or the
snippet the user just copied reappears as a fresh capture.

Read file URLs **before** strings: a Finder copy carries both, and the URLs are
the more useful of the two.

## pty and process spawning

**Use `posix_spawn`, not `fork()`.** Forking a process with a live Swift/ObjC
runtime, GCD queues and CoreFoundation is genuinely unsafe — only
async-signal-safe calls are legal between fork and exec, and the Swift runtime
is not one. `posix_spawn` does fork+exec atomically inside libsystem.

The sequence that gives a *controlling* terminal:

1. `posix_openpt(O_RDWR | O_NOCTTY)`, `grantpt`, `unlockpt`, `ptsname`.
2. `posix_spawnattr_setflags(&attr, Int16(POSIX_SPAWN_SETSID))` — child becomes
   a session leader.
3. File actions: `addclose(master)`, then **`addopen(0, slavePath, O_RDWR, 0)`**,
   then `adddup2(0, 1)` and `adddup2(0, 2)`.

Step 3 is the trick. On BSD — and therefore macOS — **the first terminal a
session leader opens becomes its controlling terminal.** That gives working job
control without a `TIOCSCTTY` ioctl the parent cannot issue.

Other things that matter:

- Spawn the shell with **`-l`** (login). A GUI app's inherited `PATH` is not the
  user's `PATH`; without `-l` their tools are missing.
- `ioctl(fd, TIOCSWINSZ, &size)` **before** spawning, so the first prompt draws
  at the right width.
- On resize, `TIOCSWINSZ` *and* `kill(-pid, SIGWINCH)`. Without the signal the
  kernel knows the new size but the running program does not.
- Teardown must signal the **process group**: `kill(-pid, SIGHUP)`. Signalling
  only the shell orphans its children — the thing you were actually running —
  still holding the pty. Then `SIGKILL` after a grace period; going straight to
  SIGKILL skips shell cleanup like history flush.
- `waitpid` to reap, or you leave a zombie.
- Set the master fd non-blocking and drive it from a `DispatchSourceRead`.
  `EAGAIN` on a non-blocking fd is normal, not an error.

## UTF-8 across reads

A codepoint can be split across two `read()`s from a pty. Decoding each chunk
independently corrupts every emoji and accented character at a buffer boundary.

Hold incomplete tails:

```swift
var bytes = utf8Pending + Array(data)
utf8Pending = []
// ... if index + length > bytes.count { utf8Pending = Array(bytes[index...]); break }
```

This is the classic bug in hand-rolled terminals. It has a test.

## Accessibility API

`AXIsProcessTrusted()` checks; `AXIsProcessTrustedWithOptions` with
`kAXTrustedCheckOptionPrompt` shows the system dialog. There is no programmatic
grant.

**Do not poll for selected text.** `AXUIElementCopyAttributeValue` is a
synchronous IPC call into another process. Several times a second, forever, it
is measurably costly to *both* processes and is the most common reason apps in
this category get called sluggish.

Use `AXObserver` + `kAXSelectedTextChangedNotification`, re-pointed when the
frontmost app changes (itself a workspace notification). Not every app
implements it — `AXObserverAddNotification` failing is normal and just means the
feature does not work there.

For the selection's on-screen rect, ask for `kAXSelectedTextRangeAttribute` then
`kAXBoundsForRangeParameterizedAttribute`.

**AX reports top-left-origin coordinates; AppKit windows are bottom-left.**
Convert via the containing screen's height, and pick the screen by containment —
assuming `NSScreen.main` breaks on multi-display setups.

## CoreAudio

Volume is `kAudioHardwareServiceDeviceProperty_VirtualMainVolume` on the default
output device, scope `kAudioDevicePropertyScopeOutput`.

Register an `AudioObjectAddPropertyListener` so the hardware volume keys move
your slider without a timer.

**Guard against the feedback loop**: the listener fires on your own write, which
sets your published value again mid-drag and makes the knob stutter. Flag it.

## Brightness

No public API. Two private paths:

- `DisplayServicesGetBrightness` / `DisplayServicesSetBrightness` — works on
  Apple Silicon internal panels.
- `IODisplayGetFloatParameter` / `IODisplaySetFloatParameter` on an
  `IODisplayConnect` service — works on Intel and external displays, returns
  nothing on Apple Silicon internal.

Try DisplayServices first, fall back to IOKit, and **hide the control** if
neither resolves. Resolve both via `dlopen` — never link a private framework, or
the app fails to launch outright the day Apple moves it.

## TCC and code signing

macOS keys permission grants to a **code-signing identity**. An unsigned binary
gets a new identity on every rebuild, so the user re-grants Accessibility after
every single build.

`codesign --force --sign - MyApp.app` (ad-hoc) with a stable bundle identifier
keeps grants across rebuilds. It does *not* satisfy Gatekeeper for distribution
— that needs Developer ID and notarisation.

Also: **a missing usage string in Info.plist does not produce a denied prompt —
it kills the process.** Include a usage string for every permission the app can
ever request, including features the user may never enable.

## EventKit

macOS 14 split calendar access into full and write-only.
`requestFullAccessToEvents` for reading, with `requestAccess(to:)` for older
systems.

`EKEventStore` is expensive: creating one opens a connection to the calendar
daemon and pulls indexes into your process. Create it when the feature opens and
**drop the reference** when it closes. Changes arrive via `.EKEventStoreChanged`,
so no polling is needed while it is alive.

## Carbon hotkeys

The only global-hotkey API that does **not** require Accessibility permission.
Both `NSEvent.addGlobalMonitorForEvents` and `CGEventTap` do.

`RegisterEventHotKey` registers with the window server, so it fires over
full-screen apps. The callback is a bare C function pointer with no context, so
it must trampoline through a singleton.

A non-`noErr` return almost always means another app already owns the
combination. Log it — failing silently here is very confusing to debug.

## Unix sockets from Swift

`URLSession` cannot open `AF_UNIX`. There is no configuration for it. You write
`socket`/`connect`/`read`/`write` yourself.

`sockaddr_un.sun_path` is a fixed 104-byte C array imported into Swift as a
tuple. To write a path into it:

```swift
withUnsafeMutableBytes(of: &address.sun_path) { $0.copyBytes(from: pathBytes) }
```

Reject paths that do not fit rather than truncating — a truncated socket path
fails in a baffling way.

Set `SO_RCVTIMEO`, or a wedged peer hangs your dispatch worker forever.

Docker's Engine API uses **chunked transfer encoding** for `/containers/json`,
so the de-chunking branch is load-bearing, not defensive. Send
`Connection: close` so you can read to EOF instead of implementing keep-alive
framing.

Docker's socket is in one of four places depending on Docker Desktop version,
Colima or OrbStack. Probe them in order.
